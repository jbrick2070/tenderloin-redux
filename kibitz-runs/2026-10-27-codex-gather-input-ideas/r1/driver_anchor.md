# Driver anchor: deliberate Gather again input

VERDICT: confirmed actual repeated-input defect warrants one connected correction; no product implementation selected before r1. The same two nodes are re-enabled immediately at `programme_gathering.gd` handoff/refresh; `fit_layout` changes the first button position when Previous appears. Eight repeated first-choice cases hit Previous, retain one choice and show step0; eight repeated second-choice cases select both remaining handoffs, while the eight paired single controls advance once. Both source and served accepted PCK match; observations use synthetic browser profiles and no data loss. Each case's snapshots/trace are retained. These are application-level actual clicks/taps, not proof of physical-phone usage or of a person's intention.

MUST CHALLENGE: compare explicit acknowledgement at a geometrically different target against reusable guarded choices and event-based repeat suppression. Avoid depending solely on a frame or short timeout when input arrival and reflow can differ. Preserve accessible keyboard/button/reader ownership, deliberate fast actions, no focus takeover, resize/reentry/review/Finish safety, same posted-order copies and no new durable state. Require actual mouse/touch/keyboard assertions at first/second and third boundaries; native and browser save/settings/legacy/quiet checks. Fixed 2MiB export cap leaves124 bytes, so proposed design must measure actual size and cannot delete unrelated content or weaken coverage. Prior art is a design reference, not a copied asset or endorsement.
