## Additional driver regression finding

After adding the review's focus assertions, the full browser run failed when clicking the layout marker while already beside it after packing. A focused reproduction retained `artifacts/m1-canvas-focus-failure.json`: the new modal was open and its back-block button briefly received focus, but final activeElement was BODY. The canvas pointerdown default focus action occurred after synchronously opening the dialog. Cancel that default while explicitly focusing the canvas before dispatch; also guard the queued dialog close handler against refocusing the canvas if a new modal is already open. The complete browser suite now checks this direct-pointer case before/after packing in both layouts. This was a production input bug, not dismissed as a flaky test.

The initial unit run also had a test-harness TypeError from passing a constructed string instead of a RegExp to doesNotMatch. Corrected the assertion itself; no production behavior was changed for it. Explanation is retained in artifacts/m1-initial-test-failure.txt.
