# Localization source and review files

This folder holds the localization metadata for the 2D edition (`browser-next/`). It is not published: GitHub Pages copies `browser-next/` only. The design is `docs/I18N_PLAN.md`; this file is the contributor's short version.

## The rules

- **English is the source of truth.** The English text stays in the JavaScript tables it lives in (`characters.js`, `ending/text.js`, `visits/text.js`, `story.js` and the others). Nothing here or in a catalog changes an English byte. With no locale selected the game behaves exactly as before.
- **Catalog keys are the English text the 2D edition shows**, after the `webLine`, `web` and `webText` overrides. A context name (the table path, such as `characters.PANEL_TEXT.scReady`) is added only when one English string needs two translations.
- **Fallback is per string**, and a composed sentence falls back whole. In a locale, fallback English is marked `lang="en"`.
- **Settings.** The language lives in the fork settings key `tenderloin-redux.browser-next.settings.v1` (`language`, `languageOffer`, `addressForm`). The shared save `tenderloin-redux.godot.save.v1` gains nothing. The game never switches language on its own; `?lang=xx` is for links and QA and is never stored.
- **Not translated** (D8): the brand, street names on the map, the district's official name, names and addresses, organization names, source titles and URLs, attributions, key names, "RISE" and "So What".
- **A locale reaches players only when `browser-next/locales/index.json` lists it as `shipped`**, which happens only after its release gates (D10). A partly translated locale is reachable with `?lang=xx&preview=1`.

## Files

| Path | What it is |
|---|---|
| `i18n/source.json` | Generated by `node scripts/i18n.mjs extract`: every msgid with its table paths, placeholder signature, length class, speaker, addressee and sensitivity tags. A test fails when it is stale. |
| `i18n/review/<code>.json` | Review status per batch (written by `init`); `status` becomes `shipped` only when the D10 gates pass. |
| `i18n/glossary.csv`, `i18n/characters.md`, `i18n/style/<code>.md` | Glossary, character sheet and per-locale style guides (added with the first locale). |
| `browser-next/locales/index.json` | The runtime manifest, generated by `manifest`: per locale `code`, `endonym`, `dir`, `status`, `coverage`, `sha256`. |
| `browser-next/locales/<code>.json` | A runtime catalog: `{ "format": 1, "locale": "<code>", "messages": { "<English>": "<translation>" } }`, with optional `context`, `narrow` and (Arabic only) `address` sections. No review notes, status or names of reviewers. |
| `browser-next/i18n.js` | The runtime: `LOCALES`, bootstrap strings, `readCatalog`, `loadCatalog`, `setLocale`, `L`, `t`, `format`, `plural`, `select`, `list`, `num`, `isolate`, `html`, `pseudo`, `canvasFont`. |
| `scripts/i18n.mjs` | The tooling, with the table registry (`REGISTRY`, `EXCLUDED`). |

## Translating

- Keep every placeholder: `%s`, `%d`, `%.1f`, `%%` and `{name}`. Reorder with positional forms (`%2$s`). A select or plural variant may leave out the argument it is chosen by, positionally.
- Keep newlines, the speech envelope `Name: "…"` (with ASCII quotes), curly quotes, and the protected tokens (Tenderloin Redux, E, WASD, Enter, Esc, Shift, F5, BPM).
- Keep the English's tags exactly (`<kbd>E</kbd>` stays `<kbd>E</kbd>`, in the same order, with the same attributes), and add none of `<`, `>`, `&`, `"` or `'` beyond what the English has. Do not add URLs or domains the English does not have, or control characters (the bidi isolates U+2066 to U+2069 and LRM/RLM are allowed).
- A translation may be at most four times the English plus 120 characters.
- Plural forms use only the locale's CLDR categories and always include `other` (es: one, many, other; vi and th: other; ar: zero, one, two, few, many, other). A category you leave out falls back to `other`, so Spanish usually needs only `one` and `other` (`many` is for millions).

The validator (`readCatalog` in `browser-next/i18n.js`) drops any entry that breaks these rules, and that string shows in English.

## For code authors (I2): text and HTML

- `t(english, ctx)`, `L(english, ctx)` and `format(template, args, flavor)` return **text**. In English they return exactly what the code produced before, byte for byte. Use them for `textContent`, `setAttribute`, `aria-*` values set from code, `document.title` and the canvas.
- Inside an HTML template, a `t()`/`L()`/`format()` value may stand **only where the code already inserts the same English unescaped** (a table value in a `show()` template). That is safe because a validated translation adds no markup character or tag beyond its English, and `setLocale` accepts only validated catalogs.
- Anywhere else in HTML, and for every new site, use `tHTML(english, ctx)` (escaped `t()`) or `html(english, ...parts)` (escaped text with already-escaped HTML parts for `%s`). In English these equal `esc(english)`, so they are safe drop-ins where the code escapes today.
- Never pass player input, a file name or other non-catalog text through `html()` parts unescaped.

## Adding a locale (docs/I18N_PLAN.md 2.13)

1. Add an entry to `LOCALES` in `browser-next/i18n.js` (code, endonym, `html`, `intl`, `dir`, plural categories) and, after review, its bootstrap strings in `BOOT`. es, vi, ar and th are already there.
2. `node scripts/i18n.mjs init <code>` writes `browser-next/locales/<code>.json` with empty `messages` and `i18n/review/<code>.json` with batches.
3. Write `i18n/style/<code>.md` (register, pronouns, quotes, numbers) and add glossary columns.
4. Draft, check (`node scripts/i18n.mjs check <code>`), review and run in-context QA with `?lang=<code>&preview=1`.
5. `node scripts/i18n.mjs manifest`, then `npm test` and `npm run next:locales -- <code>` (I7).
6. Set the review file's `status` to `shipped` only when the D10 gates pass, and run `manifest` again.

A new right-to-left script, or a script without spaces between words, also needs the RTL CSS (I3) and canvas wrapping (I4) work.

## Commands

```
node scripts/i18n.mjs extract          # regenerate i18n/source.json after any English change
node scripts/i18n.mjs check [code]     # validate catalogs and the manifest
node scripts/i18n.mjs init <code>      # start a locale
node scripts/i18n.mjs manifest         # regenerate browser-next/locales/index.json
node scripts/i18n.mjs pseudo [qps-ploc|qps-rtl]   # print a pseudo catalog (tests only; never written to browser-next)
```

`merge` (fuzzy carry-over of translations whose English changed) and the spreadsheet `export-sheet` and `import-sheet` commands are planned with the first locale (I5).
